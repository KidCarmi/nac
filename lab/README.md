# ASTRA wired NAC lab handoff to OPUS

This branch is a **sanitized evidence handoff**, not a pilot product candidate. The preserved baseline uses NAC commit `4911d2d940797aeb41be3815af1cf23b25573dc1`, FreeRADIUS `3.0.26`, vEOS-lab EOS `4.29.2F`, and lab adapter SHA-256 `7c2d77197495e28e6fd1724e60b30836be4314d812a936c58d326ef2ed4dda30`. The original [report](report.md), [evidence matrix](evidence.md), [rerun instructions](rerun.md), [topology export](NAC-Wired-Qualification.unl), [sanitized configuration](configs.sanitized.txt), [adapter source](nac_radius_adapter.py), [adapter log](nac-adapter.jsonl), [RADIUS/CoA capture](radius.pcap), [endpoint EAPOL capture](endpoint-eapol.pcap), and [public test CA certificate](nac-ca-public.pem) came from the proven baseline.

The later [independent qualification report](qualification-report.md) clarifies the NAC outage and CoA behavior and links the corrected, repeatable [baseline regression run](runs/baseline-20261106T084558Z/manifest.json). That run has six PASS results with per-run decisions, EAPOL, RADIUS, switch observations and fresh TCP probes. The [outage clarification](clarifications.md) has its own action transcript and packet captures. These files do not claim to validate OPUS's candidate installer, UI, versioned policies, outage workflow or product CoA action.

A separate, unstarted [candidate topology](NAC-Pilot-Candidate.unl) and clean Ubuntu 24.04 control template are prepared inside EVE; see [candidate preparation and verification](candidate-prep.md). The candidate nodes must not run concurrently with the baseline because they use the same internal address plan. The candidate OS image remains inside EVE and is not included here.

For OPUS's switch parser, this image accepts **`show dot1x hosts | json`**. The requested `show dot1x hosts detail | json` returns `% Invalid input`. An authenticated Et1 example is [switch-session-observed.json](switch-session-observed.json). [coa-radius-timeline.txt](coa-radius-timeline.txt) is decoded from the original capture: request ID 233 got NAK 402; request ID 172 with NAS-IP-Address and NAS-Port-Id got ACK 200; the switch then initiated Access-Request and received VLAN 10. The earlier CoA sender was a lab script, not a product workflow. After the corrected CoA there was no manual reauthentication or endpoint reconnect, but the operator did refresh the endpoint IP before testing reachability.

The original and new exported pcaps/logs were checked against the lab's current root-only RADIUS secret, service token and configured passwords: **zero known plaintext matches**. The bundle contains no CA/server/client private key, shared-secret value, service token or vendor image. The public certificate fingerprint is SHA-256 `a7c0b70440431feb392fc06f5e87d2f403e844ab39798a489a41d678a8c99c81`. The [runner](run_baseline.py) is a local-workstation tool and needs the existing `D:\AI\nac-wired-lab\eve_guest.py` and its pinned host-key/credential setup; it deliberately refuses candidate mode until the product workflow is delivered.

ASTRA's [API/evidence contract](api-evidence-contract.md) now reflects OPUS draft v2 (`df0f1a9`): **no authorization cache**, fail-closed new logins during outage, imported outage-log provenance, and FreeRADIUS `3.2.5` as an explicit candidate upgrade from this lab's proven `3.0.26`. OPUS has not named a pilot test candidate; his `fd604b0`, `94ee467` and `44a3e95` commits remain non-candidates.
