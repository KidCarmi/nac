# Agent-operated test transcript

All times below are on 2026-11-09 in the EVE guest clock. The packet timestamps are in the pcaps; the CLI and TCP results were observed interactively and transcribed here. This is a fixed FreeRADIUS platform test with **no nacd**.

1. **Initial reference attempt:** Port `1/1/1` had `aaa authentication port-access dot1x authenticator` → `enable`; global authenticator was absent. Endpoint `wpa_supplicant -B -i ens3 -D wired -c /root/wired-valid.conf` reported `CONNECTING`/`Unauthorized`. Captures: EAPOL-Start at endpoint and switch taps, no EAP response or RADIUS. `show port-access clients` reported none.
2. **Configuration correction:** Switch `aaa authentication port-access dot1x authenticator` → `enable` in global config. Switch immediately showed the endpoint `In-Progress`. Operator restarted only the interface-specific supplicant with `wpa_cli -i ens3 terminate` followed by the same `wpa_supplicant` command.
3. **Baseline authentication:** Endpoint `wpa_state=COMPLETED`, `suppPortStatus=Authorized`, `EAP state=SUCCESS`. `show port-access clients`: `1/1/1 00:50:00:00:3e:00 dot1x Success RADIUS_3940042852`. Detailed switch session: `wired-endpoint-01`, `dot1x Authenticated`, role `RADIUS_3940042852` Applied. Endpoint `10.70.10.50/24`: corp HTTP 200; remediation HTTP 200. Corp service node independently reached peer `10.70.10.11:8080` with HTTP 200.
4. **Fixed quarantine:** FreeRADIUS `mods-config/files/authorize` returned `Aruba-User-Role := "quarantine"` for `wired-endpoint-01`; FreeRADIUS config check passed and the service restarted. Operator ran `port-access reauthenticate interface 1/1/1`. Switch session became `dot1x Success`, role `quarantine` Applied. With the **same** endpoint address: fresh corp TCP timed out after 3.001 s (`000`); healthy same-subnet peer TCP timed out after 3.000 s (`000`); remediation returned HTTP 200. The RADIUS pcap contains Access-Accept VSA 14823/1=`quarantine`.
5. **Fixed restore:** Only that FreeRADIUS role line changed to `corp`; config check and service restart passed; operator again ran `port-access reauthenticate interface 1/1/1`. Switch session became `dot1x Success`, role `corp` Applied. Endpoint still `10.70.10.50/24`: corp HTTP 200, same-subnet peer HTTP 200, remediation HTTP 200. RADIUS pcap contains Access-Accept VSA 14823/1=`corp`.

**Interpretation:** The original missing session was an integration/configuration error. This exact simulator enforced the tested IPv4 per-session port-access policy. The role pair proves fixed RADIUS control of reachability. It does not yet prove KidCarmi/nac control, dynamic CoA role changes, shared-port isolation, IPv6, DHCP behavior or established-flow termination.
