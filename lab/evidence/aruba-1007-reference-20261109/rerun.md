# Bounded rerun

Use the [topology export](Aruba-Role-ACL-1007.unl) in the existing EVE VM or a recoverable copy. Supply a separately authorized Aruba image matching the recorded hash and fresh disposable PKI and RADIUS secret. Do not reuse the omitted credentials. Keep the rc10 topology stopped or isolated.

1. Start Aruba node 61, endpoint 62, corp 63, remediation 64, FreeRADIUS 65 and peer 66. Verify the interface mapping and `group_fwd_mask` in the [report](README.md). Use `show interface 1/1/1 brief` to confirm port up.
2. Disable TX offload on endpoint and service `ens3`: `ethtool -K ens3 tx off tso off gso off`. Confirm corp and remediation HTTP 200 from the endpoint and peer HTTP 200 from the corp node before filtering.
3. Configure FreeRADIUS 3.0.26 EAP-TLS against the disposable CA, `require_message_authenticator=yes` for switch `10.70.99.1`, and validate with `freeradius -Cx`. Set only `wired-endpoint-01` to return local role `corp` initially. The included [sanitized configuration](sanitized-config.md) identifies the relevant fields.
4. On Aruba configure the management-VRF RADIUS server; **enable 802.1X both globally and under `interface 1/1/1`**. Disable MAC authentication and remove the preauth role for this reference run. Define local `corp` and `quarantine` roles, with `q-policy` permitting remediation and denying other IPv4. Inspect `show port-access role name quarantine` and `show port-access policy q-policy`.
5. Start `tcpdump` concurrently on endpoint tap `vunl0_62_0`, switch access tap `vunl0_61_1`, switch control tap `vunl0_61_0` and RADIUS tap `vunl0_65_0`, filtering EAPOL or UDP/1812. Use `timeout 40`, `-c 200`, and `-w` as in `qualification/aruba_tap_capture_guest.py`. Also retain `wpa_supplicant` and FreeRADIUS logs. The successful EAPOL path should be Start → EAP exchange; control path Access-Request → Challenge → Accept. Capture both VM taps so an empty server trace cannot be mistaken for no switch transmission.
6. Start `wpa_supplicant -B -i ens3 -D wired -c /root/wired-valid.conf`. Expect `wpa_cli -i ens3 status` to show `COMPLETED` and `Authorized`. Verify `show port-access clients`, detailed client status, endpoint address/route, and fresh TCP to corp, remediation and peer.
7. Change the **fixed FreeRADIUS** role line from `corp` to `quarantine`, validate config and restart FreeRADIUS. Explicitly run `port-access reauthenticate interface 1/1/1`. Confirm RADIUS VSA 14823/1=`quarantine`, switch role `quarantine`, same endpoint IP, corp/peer timeouts and remediation HTTP 200. Restore role `corp` with the same explicit reauth; confirm all three HTTP 200.

This reference sequence does not send CoA. Test CoA and KidCarmi/nac integration only after this fixed-policy gate passes. Classify a displayed role without successful TCP probes as inconclusive.
