# Rerun the fresh rc10 console qualification

Use an authorized vEOS-lab 4.29.2F image and the isolated EVE topology `NAC-Pilot-DHCP.unl`. Do not copy the disposable CA private key, RADIUS shared secret, endpoint private key, eAPI password or vendor image into evidence. The fresh control overlay and older baseline overlays remain separate. The only physical data NIC on the endpoint is Ethernet1 via its `ens3` guest interface.

1. From `D:\AI\nac-wired-lab`, inspect the pinned candidate and hashes in `install.txt`; install the rc10 archive according to KidCarmi/nac `docs/pilot/installation.md`, supplying a lab CA that issued the endpoint certificate and matching FreeRADIUS server certificate/key. Verify `freeradius -CX`, services, `/readyz`, binary SHA-256 and fresh DB counts. The present run used a 45.8-second install. The guest OS SSH repair was a disposable overlay prerequisite, not a product installation step.
2. Ensure EOS port Ethernet1 has `dot1x pae authenticator` and `dot1x port-control auto`, corp VLAN10 and quarantine VLAN20. Keep only isolated bridges. Set separate 120-second DHCP scopes and HTTP services on `10.70.10.10:8080` and `10.70.20.10:8080`; verify each from its own segment and IP forwarding 0.
3. In the NAC console, sign in; register the switch with its generated EOS config, apply that config on EOS and save. Configure the trusted eAPI CA with verification on. Probe management and verify EOS version. The console handles switch record and mappings; switch CLI action is still required.
4. Start bounded captures and probes: `python qualification/run_dhcp_candidate.py capture-start --candidate b39649f138e126ed6689a53b590855061042e341 --run <unique-run>`; `python qualification/run_dhcp_candidate.py probe-start --candidate ... --run <unique-run> --seconds 3600`. The capture runner rotates at 2×8 MiB per interface. Give the endpoint one DHCP data NIC, no management bypass.
5. With policy v1 default deny, start `wpa_supplicant -i ens3 -D wired -c <valid-profile> -B`; verify EAP-TLS certificate validation, NAC unbound rejection and blocked corp TCP. In Devices add the endpoint record, then bind the validated issuer+serial from that session. In Policy add `identity.bound eq true` → allow corp, preview captured decision, publish and start a fresh endpoint authentication. Verify RADIUS VLAN10, eAPI, DHCP lease, route/DNS and both fresh TCP targets.
6. Leave the endpoint and switch to react naturally. In the session console choose Quarantine, record action timestamp, CoA state, new session and observations; keep probes until a quarantine DHCP lease and fresh quarantine TCP appear or an explicitly stated timeout. Then choose Restore and repeat. Never count a manual `networkctl renew`, link toggle or supplicant restart as automatic recovery. Do not infer application access from CoA-ACK or VLAN alone.
7. Before an interactive Account password change, prepare a separate token. Have the operator submit a new 12+ character password on the Account page. Verify old password and token both return 401. The helper `fresh_ui_token_guest.py` keeps the token inside the isolated control guest and prints only HTTP status codes.
8. Stop captures/probes and fetch them with `capture-stop`, `probe-stop`, `capture-download`, `probe-fetch`. Run `pcap_timeline.py`, `dhcp_packet_timeline.py`, and `analyze_linux_lease.py` using the recorded CoA timestamps. Verify service health again. Compare NAC DB/API observations, RADIUS, switch session and endpoint probes. Use `verify_package.py <package-dir>` on the published package.

The control-node browser at 127.0.0.1:18450 is a disposable tunnel for this run. Fresh reruns need a new control guest, fresh credentials and a unique run ID; do not reuse this instance as a clean install. Windows addressing results and one-hour Linux lease results are separate packages with separate timing claims.
