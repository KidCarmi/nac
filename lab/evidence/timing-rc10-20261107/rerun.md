# Rerun the rc10 saved-config and same-VLAN measurements

Use the isolated `NAC-Pilot-DHCP.unl` topology and the exact rc10 binary hash in `findings.md`. The [full installation and endpoint prerequisites](https://github.com/KidCarmi/nac/blob/fa2950c/lab/evidence/pilot-closeout-20261107/rerun.md) apply. Keep EVE IP forwarding off, other EVE labs stopped, the Windows endpoint on one DHCP NIC, and the corp/quarantine services independently healthy. The following helpers run from the `D:/AI/nac-wired-lab` workspace; use a workspace virtual environment with Paramiko. No command prints test keys or shared secrets.

1. Record `df -h` on EVE, `run_dhcp_candidate.py topology/health`, `clean_rc9_vm.py --rc10` `/version` and binary SHA-256, and the Windows OS/NIC/lease. The run here had 11 GiB EVE free and a 120-second DHCP lease. Use a unique run ID for each bounded capture directory.
2. Read `SWITCH_ACTION=persistence_status` through `eve_guest.py --script qualification/dhcp_switch_guest.py`. With the isolated switch running rc10 RADIUS `10.70.99.4` and `nac-eapi` TLS, run `SWITCH_ACTION=save_rc10`. Verify `STARTUP_MATCHES_RC10 True`. Start bounded captures and the already installed Windows `NACLabWiredProbe` task. Run `DHCP_TRANSITION_ACTION=reboot_dhcp_switch` through `eve_guest.py --script qualification/dhcp_transition_guest.py`. Wait for the EOS console prompt, then check `persistence_status`; a failed early prompt check is not a configuration failure.
3. Verify fresh EAP-TLS Access-Accept VLAN 10, NAC eAPI observation, corp TCP success and independent service health. Use the documented NAC API or console Quarantine, then Restore. The API helper is `RC10_ACTION=quarantine|restore python3 -` through `clean_rc9_vm.py --rc10 --script qualification/rc10_product_action_guest.py`. If the previous disposable Account password is unknown, `reset_rc10_lab_admin_guest.py` uses the documented local recovery command and revokes old lab tokens; record this manual operator action. It changes no switch or endpoint setting.
4. For the same-VLAN run, start a new bounded capture and fresh Windows probe, record an idle control, then run `RC10_ACTION=reauth` three times with at least 45 seconds between actions. The helper prints each CoA creation timestamp. Run `SWITCH_ACTION=reauth_local` three times, again separated by recovery windows; the helper uses the EOS-supported `dot1x re-authenticate Ethernet 1` and prints switch clock brackets. Keep certificate, port, VLAN, DHCP address and service targets unchanged.
5. For the controlled packet diagnostic, `send_no_vlan_coa_guest.py` is lab-only and reads the disposable secret from a root-only file through `radclient -S`. Run it once without `LAB_COA_VLAN`, then three times with `LAB_COA_VLAN=10`; it prints only action times and response codes. This is separate from a NAC product action. Compare the captured tunnel TLVs with `compare_coa_tunnel_attrs.py`; a NAKed bare CoA does not prove a safe product alternative.
6. Stop the Windows probe task after recovery and retrieve `C:/NACLab/probe.jsonl` with `windows_data_vm.py --segment corp --fetch`. Stop and download the four bounded pcaps with `run_dhcp_candidate.py capture-stop/capture-download`. Use `summarize_windows_probe.py`, `summarize_samevlan.py`, and `pcap_timeline.py` to attach fresh TCP, DHCP, EAPOL and RADIUS timestamps to the exact action. Keep the old-segment denial and new-segment reachability as separate measurements. The probe samples about once per second; its maximum file size is 8 MiB, and each pcap is limited to two 8 MiB files.

The one-hour DHCP lease study is a separate upcoming run. Do not infer its result from these 120-second captures. Any future run must record its observation deadline before transition and preserve natural client behavior before a manual-renewal diagnostic.
