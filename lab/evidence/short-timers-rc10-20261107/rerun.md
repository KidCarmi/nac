# Reproduce the rc10 short T1/T2 follow-up

Use the isolated `NAC-Pilot-DHCP.unl` EVE topology and the exact rc10 candidate and dnsmasq package hashes in [findings](findings.md). The earlier [default-timer comparison](https://github.com/KidCarmi/nac/tree/8db6fe899809c2a20db741d08f72e8e3711680e1/lab/evidence/dhcp-server-comparison-rc10-20261107) explains staging dnsmasq on the original two service guests and includes the unchanged baseline configs. This package contains the helper scripts and complete measured pcaps/probes. Run `python verify_package.py .` after downloading it.

1. Verify EVE VM 102, vEOS 4.29.2F, NAC rc10 `b39649f138e126ed6689a53b590855061042e341` and nacd SHA-256 `35699eac162cc2a7315efced101bee3ec18ed87ab1cb108f06f9bb1a7b48195e`. Confirm no active Et1 session, endpoint `wpa_supplicant` stopped, `ip_forward=0`, and HTTP 200 from each target on its own segment. Confirm capture and probe storage bounds before the run.
2. With dnsmasq staged but inactive, run `DHCP_COMPARE_ACTION=timers DHCP_COMPARE_PORT=32801 python3 -` and then port `32802` through `eve_guest.py --script qualification/dhcp_compare_console_guest.py`. This copies each original dnsmasq config and appends option 58/59 as shown in [config](configs.sanitized.md). Check the `dnsmasq --test` output. Run the same helper with `DHCP_COMPARE_ACTION=start` for each port; confirm only dnsmasq listens on UDP/67. Do not alter the original udhcpd config.
3. Start `qualification/run_dhcp_candidate.py capture-start --candidate <full-rc10-sha> --run <unique-id>`, then `probe-start --seconds 300` with the same candidate/run. Confirm unauthenticated corp TCP is blocked. A pre-run `networkctl down/up ens3` may clear the endpoint's old lease; record it explicitly before the primary CoA phase. Start the valid EAP-TLS supplicant with the runner's `endpoint-valid` action. Wait for an actual DHCP ACK advertising 3600/30/45 and fresh corp TCP success.
4. Use the documented rc10 product Quarantine action (UI or API); record the product CoA timestamp. Leave the endpoint untouched. Capture its T1 unicast renewal, T2 broadcast rebind, any NAK/Discover/ACK, address/route/DNS changes, switch and RADIUS state, and fresh TCP to both targets. For an early-lease consistency run, request CoA within 5 seconds after the ACK. This published run requested Quarantine 20.764 seconds after a renewal ACK, before the next T1.
5. With a verified quarantine lease and fresh quarantine TCP success, start a new **continuous 300-second** probe and capture if the first window has insufficient remaining time. Request Restore a few seconds before quarantine T1. Continue through the declared timeout, even if the switch shows VLAN10. Do not manually renew or reconnect. Record old-segment denial and new-segment reachability separately. Note that the published run's two probe files have a 13.6-second handoff gap; its DHCP capture covers the gap.
6. Stop and download all bounded pcaps and probes. Use `dhcp_packet_timeline.py`, `pcap_timeline.py`, `merge_probe_jsonl.py` and `analyze_linux_lease.py` on the local files. If automatic recovery fails, only then start a separate diagnostic capture/probe and record any manual endpoint action. The published diagnostic used `networkctl down/up` at 17:08:38.107 UTC; it is **not** an automatic recovery pass.
7. Stop the supplicant; clear the disposable switch session; use `DHCP_COMPARE_ACTION=restore` on both service guests. This stops dnsmasq, moves back its saved config and restarts unchanged udhcpd. Confirm both 120-second scopes active, each service HTTP 200, EVE forwarding off, and no temporary transfer routes or capture processes. Keep test keys, shared secrets and vendor images out of any exported artifact.

The [dnsmasq manual](https://dnsmasq.org/docs/dnsmasq-man.html) documents numeric DHCP options and the `i` four-byte value suffix. Actual DHCP packets and endpoint TCP probes remain the pass criteria.
