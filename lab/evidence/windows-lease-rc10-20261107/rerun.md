# Windows one-hour DHCP qualification rerun

This package records pinned NAC commit `b39649f138e126ed6689a53b590855061042e341` and nacd SHA-256 `35699eac162cc2a7315efced101bee3ec18ed87ab1cb108f06f9bb1a7b48195e`. The EVE topology is `NAC-Pilot-DHCP.unl`; compare its SHA-256 with `findings.md` before running. The candidate archive and disposable PKI stay in the isolated lab and are excluded here. The Windows evaluation VM uses one DHCP data NIC on Arista Ethernet1. Keep the Linux endpoint node 32 stopped.

From `D:\AI\nac-wired-lab`, use the workspace virtual environment. The saved EVE and nested guest host keys are required; the runner reads lab-only credentials from the isolated guests and does not print them.

1. Confirm the intended candidate with `qualification\clean_rc9_vm.py "curl -sk https://127.0.0.1:8443/api/v1/version" --rc10` and the binary hash with `qualification\clean_rc9_vm.py "sha256sum /usr/local/bin/nacd" --rc10`.
2. Check that EVE forwarding is zero and both services independently return HTTP 200: `qualification\run_dhcp_candidate.py health --candidate b39649f138e126ed6689a53b590855061042e341 --run NEW-RUN`.
3. Start four bounded captures: `qualification\run_dhcp_candidate.py capture-start --candidate b39649f138e126ed6689a53b590855061042e341 --run NEW-RUN`. They use a maximum of two 8 MiB files per interface.
4. Start `C:\NACLab\probe.ps1` in Windows through its existing scheduled task, or invoke it interactively with a 75-minute deadline. It records fresh corp/quarantine TCP, address, route, DNS and DHCP lease state in an 8 MiB bounded JSONL file. The probe does not renew DHCP or reconnect the NIC.
5. Confirm corp EAP-TLS admission, then request Quarantine and Restore in the NAC console. Record each CoA `created_at` from the session detail API with `qualification\rc10_coa_evidence_guest.py` or the UI timeline. Repeat close to the observed lease T1. The server sends lease option 51=3600 seconds, but no options 58/59; RFC 2131 defaults derive T1=1800 and T2=3150 seconds. Check actual client renewal in the DHCP capture.
6. Copy the Windows JSONL from `C:\NACLab\probe.jsonl` using `qualification\windows_data_vm.py --segment corp --fetch --out PATH`. This helper adds a temporary IP to the same service segment for evidence transfer and removes it in `finally`; it never routes between segments. Keep all primary endpoint measurements before this transfer. Analyze with `qualification\analyze_windows_lease.py PROBE_JSONL name=UTC,old,new [...]`.
7. Stop and download captures with `qualification\run_dhcp_candidate.py capture-stop` and `capture-download`, each with the same candidate and run ID. Use `qualification\pcap_timeline.py radius.pcap0` and `endpoint.pcap0` to correlate CoA, Access-Accept VLAN, accounting and EAPOL. If testing an established connection, run `windows_hold_probe.ps1` once with the disposable echo service and preserve its separate log/capture.

The exact UI CoA timestamps and six measured transitions in this package are in `coa-actions.txt` and `windows-lease-analysis-final.txt`. The UI run used an existing rc10 instance; a clean-instance all-console run is tracked separately. No manual endpoint renewal, reconnect or port bounce occurred during the six Windows transitions.
