# ASTRA independent qualification — `pilot-aruba-rc3`

**Did this exact build enforce access? Yes, for the tested IPv4 fresh flows.** On ArubaOS-CX Virtual.10.07.0004, a validated and bound EAP-TLS session received the `corp` role and reached the corp service. Product CoA changed the switch role to `quarantine`: corp and same-subnet peer TCP stopped succeeding, while remediation remained reachable. Restore recovered corp. The [EAPOL/RADIUS capture](evidence/auth-switch-radius.pcap), [UI CoA captures](evidence/ui-quarantine-control.pcap), [endpoint probes](evidence/ui-quarantine-probes.jsonl), [switch session](evidence/switch-ui-quarantine.txt) and [product state](evidence/A11-ui-quarantine-state.json) are separate observations.

**Did changing only a NAC policy rule change actual reachability? Yes.** With the same valid certificate, endpoint, switch port and adapter, the console changed only the bound-identity rule's segment from `corp` to `quarantine`. Preview predicted the change. After publication and a recorded switch-local reauthentication, the [new decision](evidence/A13-policy-quarantine-state.json) used policy v3 and role quarantine, the [RADIUS Access-Accept](evidence/policy-quarantine-switch-radius.pcap) carried Aruba-User-Role `quarantine`, the [switch](evidence/switch-policy-quarantine.txt) applied it, and [fresh TCP probes](evidence/policy-quarantine-probes.jsonl) lost corp while retaining remediation. Restoring v2 and reauthenticating reversed all four observations.

**Pilot verdict:** Aruba rc3 admission, rule-only policy change, role CoA and D1 reload convergence pass within the measured scope. The full standalone release remains **not qualified** on this candidate because the entire clean UI workflow, Arista regression and Windows/physical Aruba were not repeated. An operator-status wording defect was sent to OPUS. No vendor image, private key, RADIUS shared secret, admin password or token is in this package.

## Operator experience and defect

The API onboarding and identity binding were completed on the clean instance. The same instance's signed-in console completed Quarantine, Restore, rule edit, Preview, Publish and policy restoration. The browser certificate warning required the user's handoff because the installer supplied a disposable self-signed certificate. The full onboarding→binding sequence was **not** performed solely through the UI here. External administrator completion of this entire workflow on Aruba rc3 therefore remains unverified.

**Defect U1, exact d96bb74:** enable switch accounting, reconnect so NAC stores an `accounting Start` and `acct_session_id`, then open Session → Why or the CoA confirmation. Expected: unknown presence with accurate explanation that accounting Start is not current switch observation. Actual: “NAC receives no RADIUS accounting and no fresh switch observation” despite stored Start. The [A9 state](evidence/A9-final-state.json) has `acct_session_id=1794252964825` and timeline `accounting Start`; the false text is in `liveness.note`. OPUS was asked to fix wording and supply a pinned replacement for retest. This does not undermine the separately probed enforcement result.
