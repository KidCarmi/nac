The DHCP ACKs advertise 120-second leases but no explicit options 58 or 59. The observed same-segment renewals occurred about 60 seconds after each ACK, so the endpoint's effective T1 was about 60 seconds. T2 was not observed or advertised in this run; 105 seconds is the protocol default for a 120-second lease, not a measured value. Windows probe snapshots record the DHCP server, obtained/expiry times, addresses, routes, and DNS. During the VLAN changes the address list briefly became empty, then the new subnet, route and DNS appeared. The endpoint recovered automatically before each old lease would have expired. The second Quarantine was 14.5 seconds after a renewal; the first was 17.9 seconds before the expected next renewal.

For each transition the switch acknowledged CoA with Error-Cause 200, initiated EAPOL reauthentication, and FreeRADIUS returned Access-Accept with the target VLAN and `Class=nac:<decision-id>`. The NAC Console showed the current switch session on the requested VLAN and separately `endpoint_reachability=not_observed`; its claim is limited to switch state. The UI Restore was clicked and confirmed in the rc10 console. The first three actions used the documented product API because console access had been held at a disposable-certificate browser warning during those actions. These API actions must not be described as UI actions.
