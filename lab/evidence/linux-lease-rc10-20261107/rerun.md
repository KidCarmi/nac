# Linux one-hour DHCP qualification rerun

Use the [topology export](NAC-Pilot-DHCP.unl) and [sanitized configuration](configs.sanitized.md). Pin candidate `b39649f138e126ed6689a53b590855061042e341`, nacd SHA-256 `35699eac162cc2a7315efced101bee3ec18ed87ab1cb108f06f9bb1a7b48195e`, FreeRADIUS 3.2.5 and vEOS-lab 4.29.2F. Preserve the earlier Windows and 120-second lease evidence separately.

1. Shut down the Windows evaluation VM. Start only Linux endpoint node32 on the same isolated Ethernet1. Verify the endpoint has only `ens3` plus loopback, EVE forwarding is 0, and both segment TCP services return HTTP 200 from their own bridges.
2. Clear any preceding virtual switch authentication with `clear dot1x host all`. Confirm fresh corp TCP is blocked. Start bounded captures on EVE with `qualification/run_dhcp_candidate.py capture-start --candidate <full-commit> --run <unique-run>`; this limits each of four interfaces to two 8 MiB files. Install the 4,200-second-capable endpoint probe with `PROBE_ACTION=install PROBE_SECONDS=3900 python3 -` using `qualification/dhcp_probe_control_guest.py`, then start `probe-start --seconds 3900`. Endpoint output is capped at 8 MiB. Verify at least 72 MiB free on the endpoint before starting.
3. Start `wpa_supplicant -i ens3 -D wired -c /root/wired-valid.conf -B`. Verify Access-Accept VLAN10, switch EAPOL SUCCESS VLAN10 and fresh corp TCP.
4. Request Quarantine through the NAC product. Record exact CoA creation, packet CoA-ACK, RADIUS VLAN20, switch state, old TCP denial and new TCP reachability. Observe without endpoint intervention for the declared window. If the endpoint keeps the old lease, save the probe and packet snapshot *before* any manual test.
5. For a separate diagnostic, record the timestamp of `networkctl renew ens3`; observe again. If still stale, record a separate `networkctl down ens3; networkctl up ens3`. These actions cannot count toward automatic recovery. Check the quarantine DHCP ACK option 51 and whether options 58/59 are absent.
6. After a stable quarantine lease, request Restore near its derived T1. Leave the endpoint alone through T2 and the declared probe deadline. Use `run_dhcp_candidate.py probe-status --candidate <full-commit> --run <unique-run>` for a read-only liveness check; `probe-fetch` preserves interim snapshots. If the declared probe deadline precedes lease expiry, start a second passive bounded probe under a separate run ID before the first ends, then observe past expiry. This test started `linux1h-expiry-20261107` for 360 seconds at 13:14 UTC. The capture distinguishes old-server unicast renewal, broadcast rebind, and post-expiry discovery. Analyze with `qualification/analyze_linux_lease.py PROBE name=UTC,quarantine,corp --until UTC` and keep any later diagnostic in a separate phase.
7. Stop and download all captures with `capture-stop` and `capture-download` using the same candidate/run ID. Parse `radius.pcap0` and `endpoint.pcap0` with `qualification/pcap_timeline.py`, and DHCP with `qualification/dhcp_packet_timeline.py`. Record service health, storage, switch observation and NAC session decision. Do not equate a CoA-ACK, Access-Accept or displayed VLAN with application reachability; the fresh endpoint TCP probe decides.

The run-specific timestamps, observation windows and manual actions are in `plan.txt`, `findings.md` and the phase analysis files.
