The lab adapter has no authorization-result cache. It calls NAC on every successfully validated EAP-TLS post-auth event and exits failure when NAC is unavailable. FreeRADIUS may maintain EAP/TLS state for an exchange, but the outage observations show no use of a cached NAC allow on the new login. The existing session's access remained in vEOS until the session was cleared. No expiry policy for an already authorized session was configured or measured.

## CoA on the earlier active session

The earlier handoff used an active Et1 session for endpoint MAC `00:50:00:00:02:00`, identity `wired-endpoint-01`, initially VLAN 20. An operator first changed the NAC rule from quarantine back to corp through the NAC API. The CoA sender was a lab script with VLAN 10 in the request; this was **not a product CoA action**.

1. At 08:10:57.707, control node `10.70.99.2` sent CoA-Request ID 233 to vEOS `10.70.99.1:3799`, with User-Name, a colon formatted Calling-Station-Id and VLAN 10. vEOS returned CoA-NAK ID 233, Error-Cause 402 `Missing-Attribute`.
2. At 08:12:13.284, the operator's corrected sender sent CoA-Request ID 172 with User-Name `wired-endpoint-01`, Calling-Station-Id `00-50-00-00-02-00`, NAS-Port-Id `Ethernet1`, NAS-IP-Address `10.70.99.1` and VLAN 10. vEOS returned CoA-ACK ID 172, Error-Cause 200, at 08:12:13.288.
3. At 08:12:13.503, vEOS initiated a new switch-originated Access-Request for the same identity and port. FreeRADIUS returned Access-Accept VLAN 10 at 08:12:13.696. Endpoint EAPOL capture contains a new EAP-TLS exchange around this event. The endpoint and control node clocks differ by roughly a fraction of a second, so cross-capture timestamps alone should not be treated as exact ordering; the RADIUS packets in one capture establish the post-ACK reauthentication.
4. `show dot1x hosts` then reported Et1 SUCCESS VLAN 10. The operator manually changed the endpoint address from `10.70.20.50/24` to `10.70.10.50/24` and set an on-link route to the quarantine service. A new corp TCP connection succeeded and a new quarantine TCP connection timed out.

There was **no manual endpoint reconnect or operator-triggered reauthentication after the corrected CoA**, but the switch initiated reauthentication. The operator did manually renew the endpoint's IP address after the VLAN change. The old run had post-change probes, not continuously running probes, and did not test an already established TCP connection. A candidate run must close those evidence gaps and distinguish CoA request, ACK, switch-triggered EAP/RADIUS, observed switch VLAN and TCP convergence.
